# known-issues — suisei-shop-notify

## 2026-10-12 途中の1件が失敗すると、送れた分まで次の回にまた届く

**症状（コードを読んで気づいた。実際に起きたかは未確認）**
新商品やニュースが何件か同時に出たとき、Discord への通知が途中で1件失敗すると、
その回で送れた分も「送った名簿」（`known_codes.json` / `known_news_ids.json`）に残らず、次の回にまた同じ通知が届く。

**原因**
名簿を「全部送り終えてから」まとめて保存していた。途中で止まると保存まで行かない。
Discord は短い間にたくさん送ると「送りすぎ（429）」で断るので、一度に何件も出たときに起きやすい（推測）。

**直したこと**（`check.js` と `news-check.js` の両方）
- 1件届くたびに名簿へ保存する。届かなかった分は名簿に入れず、次の回に送り直す
- 1件失敗しても残りは送る。最後に実行を赤にして気づけるようにする
- 429 と言われたら、言われた秒数だけ待って送り直す（3回まで）
- テスト `check.test.js` を足した（`node --test check.test.js`。商品とニュースの両方を見る）

**元ネタ**：公式ブログ「Building effective agent automations」（2026-10-08）の
「届いたのを確かめてから記録する」。兄弟の holo / vspo / merch も同じ直しをした。

**テストを走らせるときの注意**：`node --test` だけだと `test-notify.js` まで拾って走らせてしまう。
`DISCORD_WEBHOOK_URL` が入っていると本物のテスト通知が飛ぶので、必ずファイル名を付ける。
